============================================================ 1.
INTRODUCTION
============================================================

Prompt engineering is the process of designing and refining instructions
given to a generative AI model so that it produces useful, accurate, and
consistent responses. A well-designed prompt specifies the task,
provides context, defines constraints, and describes the required output
format.

This report explores three prompt-engineering techniques:

1.  Zero-shot prompting versus few-shot prompting.
2.  Direct prompting versus a request for step-by-step problem solving.
3.  Structured output generation using a JSON schema.

Google AI Studio with Gemini was selected as the testing environment.
The experiments use practical examples involving customer feedback,
arithmetic reasoning, and invoice data extraction.

EXPERIMENT 1 – ZERO-SHOT VS FEW-SHOT PROMPTING
============================================================

3.1 Aim

To compare the performance of zero-shot and few-shot prompting on a
customer-review sentiment classification task.

3.2 Task

Classify each customer review into exactly one of the following
categories:

-   Positive
-   Negative
-   Neutral

The same three test reviews are used for both prompts to make the
comparison fair.

3.3 Test input

Review 1: “The delivery was late, but the product quality is excellent.”

Review 2: “I am extremely disappointed with the service.”

Review 3: “The package arrived yesterday.”

3.4 Zero-shot prompt

You are a customer feedback classifier.

Classify each customer review into exactly one of these categories:
Positive, Negative, Neutral.

Return only the category. Do not explain.

Review: “The delivery was late, but the product quality is excellent.”
Review: “I am extremely disappointed with the service.” Review: “The
package arrived yesterday.”

3.5 Zero-shot output – illustrative sample only

1.  Positive
2.  Negative
3.  Neutral



3.6 Few-shot prompt

You are a customer feedback classifier.

Classify reviews as Positive, Negative, or Neutral. Follow these
examples:

Review: “Amazing product, I love it!” Category: Positive

Review: “The service was terrible.” Category: Negative

Review: “The order arrived on Monday.” Category: Neutral

Review: “Very helpful staff and quick service.” Category: Positive

Now classify these reviews:

Review: “The delivery was late, but the product quality is excellent.”
Review: “I am extremely disappointed with the service.” Review: “The
package arrived yesterday.”

Return only the categories in order.

3.9 Analysis

Zero-shot prompting provides the task instructions without examples. It
is concise and useful when the model already understands the task.

Few-shot prompting includes labelled examples before the new inputs. The
examples demonstrate the expected relationship between a review and its
category. This can help the model follow the desired classification
pattern and output format.

The mixed-sentiment first review is potentially ambiguous because it
contains both a negative delivery experience and positive product
feedback. A consistent classification policy is important. In this
experiment, the overall sentiment is treated as Positive because the
positive product-quality statement is the main evaluative statement. If
a different policy is preferred, it should be defined before testing.

EXPERIMENT 2 – DIRECT PROMPTING VS STEP-BY-STEP INSTRUCTIONS
============================================================

4.1 Aim

To compare a direct prompt with a prompt that asks the model to present
concise calculation steps for a multi-step arithmetic problem.

4.2 Problem statement

A shopkeeper buys 5 notebooks for Rs. 40 each. He sells 3 notebooks for
Rs. 55 each and the remaining 2 notebooks for Rs. 35 each. Calculate the
total profit or loss.

4.3 Direct prompt

A shopkeeper buys 5 notebooks for Rs. 40 each. He sells 3 notebooks for
Rs. 55 each and the remaining 2 notebooks for Rs. 35 each. Calculate the
total profit or loss. Give only the final answer.

4.4 Direct output – illustrative sample only

The total profit is Rs. 35.

Replace this section with the exact raw response returned by Google AI
Studio.

4.5 Step-by-step prompt

Solve the following problem carefully.

A shopkeeper buys 5 notebooks for Rs. 40 each. He sells 3 notebooks for
Rs. 55 each and the remaining 2 notebooks for Rs. 35 each.

Show the calculation in clear steps: 1. Calculate the total cost price.
2. Calculate the total selling price. 3. Find the difference. 4. State
whether it is a profit or loss.

Give a concise explanation.

4.6 Step-by-step output – illustrative sample only

Step 1: Total cost price 5 x Rs. 40 = Rs. 200

Step 2: Total selling price 3 x Rs. 55 = Rs. 165 2 x Rs. 35 = Rs. 70
Total selling price = Rs. 165 + Rs. 70 = Rs. 235

Step 3: Difference Profit = Selling price - Cost price Profit = Rs.
235 - Rs. 200 = Rs. 35

Step 4: Conclusion The shopkeeper makes a total profit of Rs. 35.


4.7 Independent verification

Cost price: 5 notebooks x Rs. 40 = Rs. 200

Selling price: 3 notebooks x Rs. 55 = Rs. 165 2 notebooks x Rs. 35 = Rs.
70 Total selling price = Rs. 235

Profit: Rs. 235 - Rs. 200 = Rs. 35

Correct answer: Profit of Rs. 35.

4.8 Evaluation

Check each model response for: - Correct total cost price. - Correct
selling price for both groups of notebooks. - Correct difference between
selling price and cost price. - Correct identification of profit rather
than loss. - Clear and logically ordered explanation when requested.

The direct prompt requests only the final answer, so it should be
evaluated mainly on final-answer correctness. The step-by-step prompt
should also be evaluated on whether its displayed calculations are
correct.

4.9 Analysis

A direct prompt is efficient when only the final result is needed.
However, it provides limited visibility into how the result was
obtained.

A step-by-step instruction encourages the model to organise the
calculation into smaller, verifiable parts. This makes it easier for a
reader to inspect intermediate values and identify arithmetic errors.

This experiment evaluates the visible explanation and answer. It does
not require or attempt to obtain hidden internal reasoning from the
model.

4.10 Result

The independently verified answer is a profit of Rs. 35. Compare the
actual Google AI Studio responses with this answer and record whether
each prompt produced a correct result.

5.1 Aim

To test whether the model can extract invoice details from
natural-language text and return them in a fixed JSON structure.

5.2 Required JSON schema

The amount must be a JSON number, not a quoted string. Missing
information must be represented as null. The model must not invent
missing values.

5.3 Main prompt

You are an invoice data extraction assistant.

Extract the following fields from the input: customer_name invoice_date
amount currency

Return ONLY valid JSON.

Follow this exact schema: { “customer_name”: “string”, “invoice_date”:
“YYYY-MM-DD”, “amount”: 0, “currency”: “INR” }

Rules: - Convert dates into YYYY-MM-DD format. - Amount must be a
number, not a string. - Use INR as currency when the input uses the
rupee symbol. - Do not add explanations or Markdown. - If a field is
missing, use null. - Do not invent missing information.

Invoice text: [INSERT ONE TEST CASE HERE]

Note: The schema above illustrates the expected field types. For missing
values, the output must use JSON null. The model should preserve a
different currency when the input explicitly specifies one rather than

5.8 Analysis

Structured output prompting defines the exact keys, value types, date
format, and missing-value behaviour expected from the model. This
reduces ambiguity and makes responses easier to validate or consume in
software.

However, asking for JSON in a text prompt does not guarantee valid JSON.
A response may contain Markdown fences, extra commentary, missing keys,
incorrect types, or incorrectly interpreted dates.

For production applications, validation should be performed by a JSON
parser and schema validator. Where supported, a model API’s
structured-output or JSON-schema mode can provide stronger format
constraints. Prompt instructions alone should not be treated as a
substitute for validation.

============================================================ 6.
COMPARISON OF THE THREE TECHNIQUES
============================================================

Zero-shot prompting: - Uses instructions without examples. - Simple and
concise. - Useful for familiar, straightforward tasks. - May leave more
room for interpretation.

Few-shot prompting: - Includes examples of desired input-output
behaviour. - Helps communicate the classification pattern. - Uses more
prompt tokens. - Results depend on the relevance and quality of
examples.

Direct prompting: - Requests the answer without a detailed
explanation. - Efficient when only the final result is needed. -
Provides less visible evidence of intermediate calculations.

Step-by-step instruction: - Requests an organised, concise
explanation. - Makes intermediate calculations easier to inspect. -
Produces a longer response. - The explanation still needs independent
verification.

Structured JSON prompting: - Specifies keys, formats, and data types. -
Supports consistent machine-readable responses. - Requires parsing and
validation. - Can fail if the model adds extra text or produces
incorrect values.

============================================================ 7. OVERALL
FINDINGS ============================================================

The experiments illustrate that prompt structure influences the form and
usefulness of an AI model’s response.

1.  Examples in few-shot prompts communicate the expected classification
    pattern.
2.  Direct prompts are suitable for short answers, while explicit
    calculation instructions make visible verification easier.
3.  JSON schema instructions define a predictable response structure,
    but actual output must still be validated.
4.  Ambiguous input, especially numeric date formats and mixed
    sentiment, should be clarified in the prompt or test data.
5.  A fair comparison requires the same model, equivalent settings, and
    the same test inputs wherever applicable.

Final findings and performance percentages should be updated using the

============================================================ 8.
LIMITATIONS ============================================================

-   Generative AI responses may vary between runs.
-   A correct-looking response is not necessarily factually correct.
-   Few-shot performance depends on the quality and representativeness
    of examples.
-   Sentiment classification can be subjective when a review contains
    both positive and negative statements.
-   Numeric date formats can be ambiguous across locales.
-   Prompt-only JSON instructions do not guarantee schema compliance.
-   A small number of test cases is not sufficient to establish general
    model reliability.

============================================================ 9.
CONCLUSION ============================================================

This task provided practical exposure to three important
prompt-engineering approaches: zero-shot and few-shot prompting,
explicit step-by-step task instructions, and structured JSON output
prompting.

The experiments show that prompts should clearly define the task,
provide examples when useful, specify constraints, and describe the
expected output format. They also show the importance of independently
checking model responses rather than assuming that an answer is correct.

The most suitable prompting technique depends on the application.
Zero-shot prompting is useful for simple tasks, few-shot prompting can
guide classification behaviour, step-by-step instructions can make
calculations easier to verify, and structured output prompting is useful
when data must be processed by software.
